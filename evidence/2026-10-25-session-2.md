# Session 2 — why the warning board kept appearing, and what it took

The report was: repeated leak waves, and the tool had no effect. Session 1
fixed nine defects and reached 4/5 on labelled shapes. This session found that
4/5 was not the same as working, and fixed eight more.

## The defects, each with the measurement that found it

| # | Defect | How it showed up |
|---|---|---|
| 10 | a new group inherited a dead group's evidence window | run15: group 306 s old reported `window 884s` |
| 11 | 1 MB of churn called a cycling cache | run16: `"released 1 MB while growing 0 MB"` |
| 12 | a subprocess starting at full size was not growth | run16: group held 127 MB, window said 5 MB |
| 13 | a process that exits released nothing (introduced by 12) | wezterm-gui 632–787 MB growth, release 0 |
| 14 | `mempilot report` printed the OLDEST window | CLI said 11:45 while the daemon wrote 12:16 |
| 15 | the classifier read the window AFTER it was reset | `growth_bytes=0` for a group that grew every tick |
| 16 | a group split by which member moved | probe-children: 21 processes reported as 15, 21, then 1 |
| 17 | growth and release compared across different horizons | `"released 130 MB while growing 0 MB"` on a group holding 288 MB |
| 18 | a leak suspect needed no growth at all | zsh +1 MB, esbuild +0 MB → advisories |
| 19 | process peak was a lifetime record | bash, 1 process, reported `process count reached 38` |

Defect 15 is the one that mattered most: because closing a window resets every
counter, and the classifier ran after the close, every branch that depends on
growth was reading zero. That is why run18 scored 2/5 with three identical
misses — plateau, accumulation and cycling all fell through to the leak branch,
which needed no growth.

## What the user sees now

The complaint was the warning board. It was produced by defect 18: the leak
branch required duration and quiet time, both of which every idle process has.
A group alive 40 minutes and quiet for 40 qualified, whether it had grown 300 MB
or nothing at all.

Replayed against the actual signals from a normally loaded machine at 14:05:

```
Google Chrome  grew  13 MB  peak 19  →  leak_suspicion   (before)
zsh            grew   1 MB  peak 34  →  leak_suspicion   (before)
extensionkitser grew  0 MB  peak  1  →  leak_suspicion   (before)
esbuild        grew   0 MB  peak  1  →  leak_suspicion   (before)
bash           grew   7 MB  peak 38  →  subprocess_accumulation (before)
```

All five are silent now. `TestObservedFalseAdvisoriesStaySilent` fails on the
old classifier with exactly those five and passes on this one.

The floor is `MinSuspicionBytes = 128 MB` over the group's whole life, which is
0.8 % of this machine's RAM. A slow real leak still crosses it: 50 MB/hour for
three hours is flagged, asserted by `TestSlowRealLeakEventuallyFlagged`.

## The one remaining labelled miss is the label

run21 scored 4/5. The miss is `probe-sawtooth`, labelled "cache" on the
assumption that freeing a slice returns memory. Measured twice from the
process's own footprint — 40 s in run8, 115 s in run21 — it never decreases:

```
13.5 13.5 23.7 33.7 33.7 33.7 33.7 33.7 33.7 43.9 43.9 53.9 53.9 63.9 63.9
73.9 73.9 73.9 73.9 73.9 73.9 84.0 84.0
```

Go keeps freed heap pages mapped. The probe never releases anything, so calling
it unexplained sustained growth describes what is happening. The label is left
unchanged so the score keeps reading 4/5 rather than being edited after the fact.

## What this session does not establish

Unchanged from `FINAL-STATUS.md`:

1. **Critical pressure was never reached live.** Level 2, not 4. T1 self-relief
   and L2 managed stop remain covered by tests, not field evidence.
2. **Thresholds are chosen, not fitted.** 128 MB, 32 MB, 256 MB, 1 MB, 1200 s,
   900 s, 8 processes. Now at least each has a measured false positive it
   excludes, which is more than before — but there is still no labelled
   false-positive corpus to fit against.
3. **No 72-hour soak.**

## Growth of the evidence discipline

Each defect above is a test that fails on the old code:

```
TestHistoryRetiredWhenGroupDisappears
TestNegligibleChurnIsNotCycling
TestNewProcessArrivalCountsAsGrowth / TestPreexistingProcessesAreBaseline
TestExitedProcessReleasesItsMemory
TestVerdictSeesTheClosedWindow
TestGroupProcessCountIsWholeGroup
TestHorizonMismatchIsNotCycling / TestAccumulationWithoutWindowGrowth
TestIdleProcessesAreNotLeakSuspects / TestObservedFalseAdvisoriesStaySilent
TestProcessPeakDecaysWhenGroupShrinks / TestRealAccumulationKeepsItsPeak
```

Three runs were discarded rather than scored: run12 (probes inherited the
terminal's group), run15 (inherited history), run17 (ran on a binary missing
the last fix). Discarding them is the point — a run that measures the wrong
thing is worse than no run, because it looks like evidence.
